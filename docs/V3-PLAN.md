# مركز الحبيب — خطة الإصدار الثالث

الأساس: فرع version-2 عند 548561be. التنفيذ على version-3.

## الهدف
واجهة هادئة وواضحة تعطي الصور الحقيقية مساحة مناسبة، وتساعد الزائر على اختيار التخصص والأخصائي ثم طلب الموعد عبر واتساب. الحفاظ على هوية الموف #8d517a والرمادي #57585a والأبيض والنعناعي #77c9b6؛ استخدام النعناعي في عناصر الواجهة وليس فوق الصور.

## المرحلة الأولى — منفذة في هذا الفرع
- الصورة الرئيسية تملأ إطاراً مربعاً بالكامل باستخدام cover، دون قيود العرض القديمة 75% أو تأثيرات المزج. قد تقص الأطراف حسب نسبة الصورة الأصلية؛ لا يتم تشويه النسب.
- خلفية محايدة للصور الشفافة، وإلغاء multiply من صور الأخصائيين، وإزالة الدائرة الملونة خلف الصورة الرئيسية.
- إبقاء صور الأخصائيين كاملة باستخدام contain لحماية الوجوه؛ صور الخدمات تملأ إطارها دون padding.
- تنقيح البطاقات والمسافات والظلال والعناوين والحركات. عزل التنسيقات الجديدة داخل public-site لحماية لوحة الإدارة.
- تمييز الصفحة الحالية في التنقل، وإغلاق قائمة الجوال عند الانتقال، ورابط تجاوز إلى المحتوى بلوحة المفاتيح.
- البحث بالعربية والإنجليزية بالاسم أو المسمى المهني في صفحة الفريق، مع تصفية القسم، وعدد النتائج، وحالة عدم وجود نتائج وزر إعادة الضبط.
- استمرار الصور المعتمدة من CMS منذ العرض الأول، واستمرار طلب المواعيد عبر واتساب دون تخزين بيانات النموذج.

## المرحلة الثانية — إدارة الصور والمحتوى
1. إعدادات منفصلة لكل صورة: cover/contain ونقطة تركيز X/Y ومعاينة للجوال والكمبيوتر، مع قيم افتراضية متوافقة مع المحتوى القديم.
2. فحص نوع وحجم وأبعاد الصور عند الرفع، وتصغير نسخ العرض إلى WebP/AVIF. إزالة الفراغ الداخلي من الملف نفسه عند وجوده؛ CSS لا يكتشف الفراغ داخل الصور.
3. نشر ومسودات ومعاينة قبل النشر، وسجل تعديلات واضح وإمكانية استرجاع المحتوى.
4. توحيد ترجمة أسماء التخصصات والمؤهلات ومراجعة النصوص من المركز.
معيار القبول: تعديل الصورة يظهر في الرئيسية وبطاقات الفريق والملف من المصدر نفسه، دون وميض صورة قديمة أو قص الوجه.

## المرحلة الثالثة — تجربة طلب الموعد
1. اختيار الأخصائي من ملفه ينقل الاختيار إلى النموذج مع إمكانية تغييره.
2. تبسيط الحقول وتجميعها، ورسائل أخطاء بجانب الحقول، وإرسال طلب الموعد إلى واتساب مباشرة دون إظهار معاينة للرسالة.
3. إظهار أقرب موعد فقط إذا أدخله المسؤول؛ وقت الطلب تفضيل وليس تأكيداً.
4. اختبار القسم والتخصص والأخصائي والتاريخ ورقم الهاتف بالعربية والإنجليزية، وعدم تسريب الشكوى إلى التحليلات.
معيار القبول: رسالة واتساب صحيحة، وتحذير واضح بأن المركز يؤكد الموعد، وعدم حفظ بيانات النموذج.

2. اختبار دورة تحرير ونشر محتوى تجريبي في بيئة معزولة، وفصل بيانات المعاينة عن الإنتاج.
3. مراجعة أدوار المسؤول الرئيسي والفرعي، وحماية API وجلسات الدخول وتسجيل التعديلات.
4. تقييم نقل مخزن CMS إلى جداول مترابطة وفهارس بعد قياس الحاجة؛ نسخة استعادة وخطة ترحيل قابلة للرجوع قبل تغيير المخطط.

## المرحلة الخامسة — الأداء وإتاحة الاستخدام والإطلاق
- تثبيت إصدارات الاعتمادات بملف قفل مُراجع، وضغط الصور وتحديد sizes، وتحميل الصورة الرئيسية بأولوية والباقي عند الحاجة.
- قياس LCP بهدف ≤2.5 ثانية وCLS ≤0.1 وINP ≤200ms عند المئين 75؛ هذه أهداف وليست نتائج مقاسة حالياً.
- بيانات وصفية مستقلة للصفحات، sitemap وrobots ومشاركة اجتماعية، دون تقييمات أو بيانات طبية مختلقة.
- اختبار عرض 360 و390 و768 و1440 بكسل، الاتجاهين RTL/LTR، لوحة المفاتيح، التركيز، التباين وتقليل الحركة.
- بناء الإنتاج واختبارات الصور والحجز والكتالوج، ثم معاينة Vercel، ثم اعتماد النسخة واختيار ترقية الإنتاج مع نقطة رجوع محددة.
