# الدخول الآمن إلى لوحة الإدارة — مركز الحبيب V2

**لا توجد كلمة مرور عامة باسم `admin` في هذا المشروع.** لا تستطيع واجهة الموقع تسجيل الدخول ما لم تُضبط بيانات Supabase الخاصة بالمركز في بيئة النشر. لا تُرسل كلمات المرور أو المفاتيح السرية في المحادثات أو GitHub.

## 1. إعداد قاعدة البيانات

1. افتح مشروع المركز في [Supabase](https://supabase.com/dashboard). إذا لم يُنشأ مشروع بعد، أنشئ مشروعاً مملوكاً للمركز.
2. من **SQL Editor** نفّذ `supabase/schema.sql` *عند إنشاء قاعدة بيانات جديدة فقط*. لا تكرر تنفيذ سكربت الإصدار الأول على قاعدة موجودة دون مراجعة.
3. من **Project Settings → API Keys / Data API** انسخ **Project URL** و**anon/publishable key** المخصص للواجهة العامة. لا تستخدم **service_role** أو **secret key** في متغيرات تبدأ بـ `NEXT_PUBLIC_`.

## 2. تفعيل الاتصال على Vercel

من Vercel، ادخل المشروع **alhabib-website → Settings → Environment Variables**، وأضف:

| المفتاح | القيمة |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase مثل `https://project.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` أو `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | مفتاح `anon` أو `publishable` العام الخاص بنفس المشروع |

تم التحقق من مشروع Vercel الحالي، ولم تظهر فيه متغيرات بيئية لقاعدة البيانات؛ هذه الخطوة ضرورية بالفعل قبل عمل أي حساب.

حدد **Preview** لتجربة فرع `version-2`. ولتفعيلها في الإنتاج لاحقاً حدد **Production** أيضاً حسب خطة الإطلاق. **أعد نشر (Redeploy)** النسخة بعد حفظ المتغيرات، لأن Next.js يضمّن متغيرات `NEXT_PUBLIC_*` وقت البناء. لا تحتاج إلى تعديل الملفات أو إضافة `.env.local` إلى GitHub.

> يمكن استخدام `SUPABASE_SERVICE_ROLE_KEY` على الخادم فقط إذا أردت دعوة مدراء فرعيين من لوحة الإدارة. لا تضفه إلا لخدمة الدعوات وبعد التأكد من حماية `/api/admin/invite`.

## 3. إنشاء حساب مدير حقيقي

1. من Supabase → **Authentication → Users** أنشئ مستخدماً جديداً ببريد إلكتروني يملكه المركز وكلمة مرور قوية خاصة به. لا تستخدم `admin` كلمة مرور عامة.
2. انسخ **User UID** الذي يخص المستخدم الذي أنشأته.
3. افتح SQL Editor في Supabase وأنشئ سجل المدير الرئيسي بتغيير المعرف إلى UID الفعلي:

```sql
insert into public.profiles (id, full_name, role, permissions, is_active)
values ('ضع-هنا-UID-المستخدم-الفعلي', 'مدير مركز الحبيب', 'super_admin', '{}'::jsonb, true)
on conflict (id) do update set role='super_admin', is_active=true;
```

4. تأكد من تأكيد البريد الإلكتروني داخل Supabase، إذا كان تفعيل البريد مطلوباً.
5. افتح `/admin/login` في نشر V2 وسجل الدخول بالبريد الفعلي وكلمة المرور التي عيّنتها لحسابك.
6. إذا نسيت كلمة المرور اضغط **نسيت كلمة المرور؟**. أضف رابط `/admin/reset-password` على نطاق المعاينة ضمن **Authentication → URL Configuration → Redirect URLs** في Supabase، حتى يعمل رابط الاستعادة.

## التحقق من النجاح

- صفحة تسجيل الدخول لا تعرض تحذير «يلزم تفعيل الاتصال بقاعدة البيانات».
- تسجيل الدخول ينقلك إلى `/admin/dashboard`.
- المستخدم لديه سجل نشط في `public.profiles` بدور `super_admin`.
- تستطيع تغيير صور الأخصائيين من قسم «الأخصائيون»، وتعديل التخصصات والصور من قسم «الصور والأيقونات».

إذا بقيت شاشة الدخول تعرض «Supabase غير مهيأ» بعد إضافة المتغيرات، فتأكد من أنها أُضيفت إلى **بيئة Preview الخاصة بفرع `version-2`** وأن إعادة النشر تمت بالفعل. الكلمات السرية لا تُنشأ تلقائياً من GitHub أو من صفحة الدخول.

## لماذا لا ننشئ اسم مستخدم admin وكلمة مرور admin؟

هذا يُحوّل لوحة الإدارة الصحية إلى هدف سهل للتخمين. الموصى به هو بريد إداري مملوك للمركز وكلمة مرور قوية فريدة مع Supabase Auth، ومع تفعيل MFA لاحقاً عند توفره. يمكن تغيير البريد من Supabase دون تغيير الكود. لا تدخل بيانات الاعتماد في GitHub أو في هذه المحادثة.
