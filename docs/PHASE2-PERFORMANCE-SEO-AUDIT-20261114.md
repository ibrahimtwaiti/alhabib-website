## 3. الصور والخطوط

- عنصر LCP على الصفحة الرئيسية: img.hero-image؛ تقرير Lighthouse سجل طلباً بلا fetchpriority=high.
- جرى تحميل خط IBM Plex Sans Arabic وPlus Jakarta Sans عبر CSS @import من Google Fonts؛ أشار تقرير Lighthouse إلى فرصة بنحو 740 ms في موارد تحجب العرض. هذا تقدير وليس تحسناً مضموناً.
- الصورة الأساسية الحالية: 116,116 بايت عبر API الأصلي، مقابل 55,104 بايت عبر Next Image optimizer لمقاس 640px؛ اختبار نقطة واحدة وليست نتيجة لكل الصور.
- إجمالي الصور المحلية في مجلد public/assets قبل التعديل نحو 60 كيلوبايت؛ فرص التحسين الأكبر في الصور المنشورة من CMS.

التغييرات: تحميل الخطوط بنظام Next.js ذاتي الاستضافة مع font-display swap، إعطاء عنصر LCP الأولوية العالية، استخدام Next Image optimizer للمسارات المحلية فقط، والإبقاء على جميع روابط الصور الخارجية متاحة. لا حذف ولا استبدال لأي صورة حالية.

## 5. SEO و404 وMetadata

كان الموقع قبل التعديل يعيد HTTP 200 لصفحات غير موجودة مثل:
/team/nonexistent-specialist-phase2-test
/specialties/nonexistent-specialty-phase2-test
/blog/nonexistent-article-phase2-test

أضيف التحقق من وجود السجل المنشور على الخادم، وإرجاع HTTP 404 عبر notFound() عند غيابه. أضيف تصميم 404 مع روابط العودة والتواصل، وأصبح Next.js يضع noindex في استجابة 404.

أضيفت بيانات صفحات مخصصة لكل من About وTeam وSpecialties وBlog وBooking وContact وAchievements وPrivacy وTerms. التفاصيل الديناميكية تستمد Metadata من المحتوى المنشور في CMS وليس قوائم ثابتة، مع canonical والرابط الاجتماعي. صفحة الإدارة لا تسمح بالفهرسة ويظل robots.txt وsitemap.xml يشملان الأقسام المنشورة دون الإدارة.

## 6. اختبار الحجز والإدارة واللغتين

تغطي مجموعة Playwright الحالية حجز واتساب والتحقق من المدخلات والروابط المباشرة للأخصائيين، وتحديث مكونات الإدارة عبر بيانات محاكاة، وأيقونات التواصل، والفلاتر والتخصصات المتعددة، والتبديل بين العربية والإنجليزية واتجاه الصفحة.

أضيفت اختبارات مستقلة للاستجابات 404، وبيانات Meta والعنوان canonical، ومنع فهرسة الإدارة، وصفحات الفريق والتخصصات المعروفة، وخريطة الموقع، وتحميل الخطوط وصور الواجهة.

اختبارات لوحة الإدارة تستخدم Mock آمن بدلاً من بيانات تسجيل دخول حقيقية، ولا تعدّل أي حساب إنتاجي أو قاعدة بيانات.

## 7. اعتماد الأداء بعد التغيير

- يتطلب الإعلان عن تحسن LCP إعادة Lighthouse على النسخة الجديدة المنشورة بنفس إعدادات الهاتف وبنفس الصور الحية.
- لا يجوز مقارنة نتيجة localhost ببيانات افتراضية مع نتيجة Production حقيقية.
- INP يحتاج رصد المستخدمين الحقيقيين وفق ضوابط خصوصية المركز.
- تحتاج صور Next Image في Production إلى اختبار HTTP 200 وعدم ظهور أخطاء 400/500.
- تجب مراجعة اختبارات GitHub وVercel Preview قبل دمج التغييرات في main.
- لا يتضمن هذا التدقيق تعديل مدة تخزين API أو تغيير صلاحيات الإدارة أو نقل البيانات.
